# React B탭 · 내 레이스 구현 계획

## 목표와 기준

1920×1080 서브모니터에서 앞뒤 간격과 피트 결정을 한눈에 읽고, 마이크 없이 스티어링 휠로 앱의 전략을 확정할 수 있게 함. [B탭 시안](B-my-race.png)의 좌우 배치와 숫자 크기를 기준으로 삼고 공통 헤더, 팀 배지, 타이어, 시간 포맷은 현재 React A탭에서 가져옴. [기존 기능 목록](프론트엔드-기능목록.md)의 체크는 PySide6 데모 기준임. 이번 구현 대상은 Start.cmd로 여는 React 앱과 24대 모의 레이스임.

## 구현 순서

1. **공통 탭과 데이터** — web/src/main.tsx에서 B탭을 활성화함. 공통 부모의 useDemo와 /ws/demo 연결 하나로 A/B를 구동함. 정렬 전 frame.cars[frame.player]로 내 차를 식별한 뒤 순위순으로 이웃을 구함. A탭의 선택 차량과 독립적임. RankDriver와 포매터를 재사용함.
2. **주변 표와 페이스** — 최근 유효한 완료 랩을 비교해 랩당 접근량을 구함. 격차가 1초보다 크고 줄고 있을 때 ceil((간격초 − 1) / 랩당 접근초)로 접근 시점을 표시함. 이미 1초 이내, 격차 확대, 분석 대기를 구분함. 상대 교체, 피트, SC/VSC, 적기, 리타이어, 새 세션에서 이전 예측을 지움.
3. **전략 편집** — race.py의 briefing, strategy.py, tests/test_demo.py의 기존 동작을 검토함. 후보 탐색은 미리보기, 확정은 앱 계획 갱신, 취소는 원복임. 직접 설정에서는 피트 랩·다음 컴파운드, 출발 전에는 시작 타이어·최대 세 번의 교체를 편집함. 현재 React 모의 레이스가 주행 중부터 시작하므로 출발 전 편집을 재현할 진입점도 마련함. 예상 피트 손실과 페이스는 근거가 있는 모의 입력을 사용하고 자료가 부족하면 분석 대기로 표시함.
4. **휠 입력** — 기존 wheel.py, README, 저장 매핑을 검토하고 앱솔루트 다이얼 위치별 A/B 직접 선택, 스틱의 후보 이동·값 변경·확정·취소를 연결함. 반복 신호가 재확정되지 않게 함. 매핑은 재실행 후 복원하고 키보드 1/2, 방향키, Enter, Esc로도 같은 흐름을 검증함.
5. **인수 검증** — React 린트·단위 테스트·빌드 및 기존 A탭 브라우저 스모크를 실행함. 아래 장면을 1920×1080과 1576×883에서 확인하고 두 화면 캡처, 실행 방법, 실물 휠 검증 여부를 기록함.

## 완료 체크리스트

- [x] P8→P7 추월에서 주변 차량과 간격이 함께 갱신되고 A에서 다른 선수를 선택해도 B의 기준은 YOU임.
- [x] 앞차 교체·피트·SC·표본 부족·DNF에서 오래된 예측이 남지 않음. 애스턴 마틴의 정상·리타이어 배지가 A탭과 일치함.
- [x] 21랩 하드 계획에서 19랩 후보를 가리켜도 현재 계획은 21랩. 취소하면 21랩, 확정하면 19랩이며 A/B 왕복 후에도 유지됨.
- [x] 마우스 없이 A→B 전환, 전략 편집, 확정·취소가 가능함. 가상 입력 검증과 실물 MOZA 검증 결과를 구분해 기록함.
- [x] 두 화면 크기에서 핵심 수치와 확정·취소가 스크롤 없이 보이고 A탭의 24명, 서킷과 6행 이벤트 로그가 정상임.

실게임 UDP와 인게임 피트·타이어·팀라디오 명령 전송은 이후 연동 단계에서 다룸.
