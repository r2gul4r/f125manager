# F1 25 Manager

라이브 My Race의 게임 피트 윈도는 세션 패킷에서 온다. 앱의 A는 게임 윈도와 현재 세트 수명을 기준으로 계산하고, B와 C는 그보다 이른 랩과 늦은 랩을 비교한다. 사용 가능한 세트의 예상 수명·장착 세트 대비 랩타임 차이, 같은 세션의 강우 예보, 실측 페이스와 피트 손실을 반영한다. 추가 교체가 필요하면 해당 시간까지 포함한다. 노면 상태와 상대의 미래 피트는 모델 추정이다. Session Analysis의 Live 및 녹화 비교는 랩 거리 32구간마다 실제로 받은 속도·페달·ERS 에너지·네 바퀴 평균 표면 온도를 표시한다. 각 구간에서 최초로 관측한 샘플을 보존한다.

추격·방어의 실시간 추세는 최근 최대 30초의 격차와 주행 중 섹터 기록으로 계산한다. My Race의 랩당 페이스와 1초권 예상은 두 차가 같은 랩을 완료했을 때 직전 최대 3개 유효 랩의 기록 차이 평균으로 갱신한다. 측정을 시작하거나 상대가 바뀌면 직전 랩 기록부터 비교한다. 현재 격차와 실제 1초권 진입은 즉시 표시한다. 라이브 플랜은 각 차량의 공개 세트, 스틴트별 유효 랩, 게임이 예고한 날씨와 누적 시간 페널티를 사용한다. 실제 입·출차와 감속 구간을 관측한 랩은 열화율 표본에서 제외한다. 자료가 부족한 컴파운드의 열화율은 상세 화면에서 Model로 표시한다. 게임의 피트 복귀 예상은 전략의 이상적인 피트 랩에 연결하고, 다른 랩은 해당 랩의 시뮬레이션을 사용한다. 예전 녹화에서 당시 저장했던 피트 비교 결과는 그대로 재생한다.

웹 대시보드의 영문과 숫자는 Windows에 설치된 [Formula1 Display Bold](https://blogfonts.com/formula1-display-bold.font)를 사용한다. 다른 PC에서 같은 모양을 보려면 Bold 파일을 해당 PC에 설치한다. 한글은 맑은 고딕으로 표시한다.

**Start.cmd**를 실행하면 Windows WebView2 전용 창이 열린다. 탭과 주소창 없이 열리며 기본 **Fill window**는 창 전체를 채운다. **Menu → Settings → Display**에서 **Window mode**를 **Fullscreen**으로 바꾸면 제목 표시줄까지 사라진다. **Windowed** 또는 Esc로 창 모드로 돌아간다. 전용 앱 창에서는 **Layout → Fit 16:9**로 비율을 고정할 수 있고, 이 경우 창 비율에 따라 여백이 생긴다. 화면 맞춤 선택은 다음 실행에도 유지된다. 기본 화면은 게임의 실제 참가 차량과 플레이어 슬롯을 표시한다. 스즈카 모의 경기 24대는 `/?source=demo`에서 열 수 있다. 행을 누르면 지도에서 해당 차를 강조한다. 타이밍 표는 차량별 모의 미니섹터를 섹터당 8칸으로 표시한다. 회색은 미통과, 노랑은 통과, 초록은 개인 최고, 보라는 이전 랩 전체 기록 대비 최고다. 타이어 이력은 왼쪽부터 장착 순서이며 숫자는 해당 세트로 완료한 랩 수다. 오른쪽 섹터 순위는 최근 완료 랩 기준이다. 오른쪽 아래에는 최근 주요 이벤트 최대 12개가 표시된다. 왼쪽 열에 최신 6개, 오른쪽 열에 이전 6개를 위에서 아래로 표시하며 방금 추가된 항목은 1.6초간 강조한다. 각 항목의 둘째 줄에는 이벤트 당시의 순위·갭·타이어 또는 플래그 정보를 표시한다. 기본 주소는 http://127.0.0.1:8765 이며 .env.example을 .env로 복사해 포트를 바꿀 수 있다. 서버 콘솔에서 Ctrl+C로 종료한다.

처음 빌드하는 Windows PC에는 Python 3.11 (py 런처), Node 24 + npm, Rust stable MSVC, Visual Studio C++ Build Tools가 필요하다. Start.cmd가 프로젝트 전용 Python 환경과 웹 빌드를 준비한다. 변경 후 프런트는 web에서 npm ci 및 npm run build, Rust는 루트에서 .venv\Scripts\python -m pip install ./rust-core로 갱신한다.

라이브 실행 경로는 F1 25 UDP → Rust 전용 수신 스레드 → PyO3 → FastAPI `/ws/live` → Live Timing과 My Race다. 게임 텔레메트리를 켜고 대상 IP를 `127.0.0.1`, 포트를 `20777`로 설정한다. 2025·2026 포맷은 자동 감지한다. Settings → Diagnostics에 바인딩 주소, 포맷, 수락·거부 패킷 수와 마지막 랩 패킷 경과 시간이 표시된다. 랩 패킷이 2초 넘게 중단되면 Stale data, 10초가 지나면 UDP disconnected로 표시하며 마지막 화면을 유지한다. 앱과 게임을 서로 다른 기기에서 실행할 때는 `.env`의 F125_UDP_HOST와 게임의 대상 IP를 수신 PC 주소로 맞춘다.

연습·예선은 남은 시간과 유효 베스트랩 기준 격차를 사용한다. 라이브 도면은 게임 UDP 트랙 ID로 선택한다. 28개 ID에 대응하는 F1 Media 원본 25장을 로컬에서 읽고, 역방향 3종은 해당 도면의 마커 진행 방향을 뒤집는다. 도면 갱신은 Pillow가 설치된 환경에서 `python assets/game-circuits/download.py`로 실행한다. 지도 자료가 없는 트랙은 게임 월드 좌표로 주행 경로를 그린다. 레이스에서 유효한 차량별 페이스·타이어 상태를 확보하면 실제 랩 수 기준으로 A/B/C를 계산한다. 노면은 날씨에서 추정한다. 첫 피트 손실은 게임 파일의 서킷별 리미터 구간 길이와 세션 제한속도로 구한 통과 시간에 기본 정차 시간을 더하고, 같은 구간의 본선 예상 시간을 빼서 계산한다. 우천 시 게임 DB의 건조·우천 시간 차이를 가산한다. 지원하지 않는 서킷·차종은 F125_PIT_LOSS_MS(기본 20000ms)를 쓴다. 같은 포맷·서킷·피트 설정·날씨 구분에 유효한 스톱이 생기면 실측 평균을 우선한다. 공개 차량의 정상 피트도 포함하며, 그린·SC·VSC는 각각 같은 조건의 표본으로 보정한다. SC/VSC 표본이 없는 동안에는 그린 손실의 60%를 모델값으로 표시한다. My Race에는 그린 플래그 기준 손실 추정값과 사용한 기록 수, 최근 피트의 예상·실제 순위와 몇 자리 앞뒤인지 표시한다. 대시보드에서 확정한 전략은 앱 안의 계획이다. 게임 피트 지시는 게임에서 조작한다.

### 실게임 녹화와 My Race 재생

FP 세이브 변경 기록기는 서버와 같이 시작한다. Steam의 F1 25 `remote` 폴더에서 중간 세션·프로필 파일을 읽고, FP1~3 및 단축 연습의 UDP 세션 UID·되감기 구간·플레이어 랩과 함께 버전별 복사본을 `F125_RECORDING_DIR/practice-saves/captures.sqlite3`에 저장한다. 기본 위치는 `data/recordings` 아래다. Steam 경로를 수동 지정할 때는 `.env`의 `F125_PRACTICE_SAVE_DIR`에 해당 `remote` 폴더를 넣는다.

게임에서 평소처럼 프로그램을 실행하면 된다. 브라우저 탭을 닫아도 서버가 실행 중이면 기록한다. [기록기 상태와 세션 집계](http://127.0.0.1:8765/api/practice-saves)에서 `Armed`는 시작 대기, `Recording`은 FP 감지다. `files`는 감시 대상 파일 수다. 0.5초 간격으로 확인하며 두 확인 사이에 덮어쓴 버전은 누락될 수 있다. FP 진입 직전의 변경과 종료 직후 30초 이내의 변경은 주행 중 변경과 구별해 기록한다. `changedFilesObserved`는 관측한 파일 변경 횟수이고, `programmeCounts: null`은 프로그램 식별 미검증이다. 랩 수와 랩타임은 UDP의 완료 랩 이력에서 확인한다.

게임 UDP를 수신하면 Rust가 세션별로 자동 녹화한다. 기본 폴더는 `data/recordings`이며 `F125_RECORDING_DIR`로 바꿀 수 있다. 웹 화면을 닫아도 서버가 실행 중이면 계속 기록한다. 약 1초 또는 512 KiB마다 수신 시각과 원본 패킷을 체크섬이 있는 zstd 청크로 저장한다. Diagnostics에서 녹화 큐 드롭과 쓰기 오류를 확인할 수 있다.

앱 재시작 후 **Session Analysis → Recorded sessions → Open in My Race**로 연다. 일시정지·배속·시간 이동을 지원하고 **Race result**는 저장된 마지막 시점으로 이동한다. 주행 중인 세션을 열면 열었을 당시까지 확정된 구간을 재생한다. 서버를 같은 게임 세션 도중 재시작하면 이후 수신분은 별도 녹화로 남는다.

**Pit rejoin comparison**은 피트 진입 직전 예상 순위와 피트 출구에서 관측한 순위를 비교한다. 한 대씩 결승선을 지나 랩 숫자가 달라져도 주행 거리가 한 바퀴 이내면 복귀 순위와 A/B/C 계산을 계속한다. 실제 한 바퀴 이상 벌어져 선두 기준 시간차를 비교할 수 없거나 진입 직전 수신이 끊긴 경우 예상 순위는 비워 둔다. My Race는 게임 일시정지 또는 수신 중단 중 마지막 예측과 기준 랩을 표시한다. 플래시백 이후 비교는 새 시도에서 시작하며, 재생 시에는 피트 출구 시점에 실제 결과를 공개한다.

검증은 `python -m pytest tests/test_recordings.py`, 앱을 빌드한 뒤 `python tests/my_race_smoke.py`로 재현한다.


 원본 계획과 진행 상태는 [마스터 계획](docs/MASTER_PLAN.md), [체크리스트](TASKS.md), [코드 감사](docs/REPO_AUDIT.md), [외부 고지](docs/THIRD_PARTY.md)에 있다. 사용자가 전달한 7개 파일은 F1_25_AI_Engineer_Codex_Plan 폴더에 원본을 보존한다.

검증 명령은 .github/workflows/phase1.yml에 있다. E2E는 requirements-web-dev.txt를 설치하고 실행 중인 서버에 대해 python tests/web_smoke.py http://127.0.0.1:8765 를 실행한다. Playwright는 설치된 Chrome을 사용한다.

## React B탭 · My Race

`Start.cmd` → **2**로 내 레이스를 연다. **1**은 A탭이다. 앞뒤 간격·주변 5행의 기준은 게임 헤더가 지정한 플레이어 차량이다. ↑ ↓ 또는 ← →로 후보를 보고 Enter로 확정, Esc로 취소한다. 직접 설정은 ↑ ↓로 항목을 고르고 ← →로 값을 바꾼 뒤 ‘Apply plan’에서 Enter를 누른다. 계획은 A/B를 왕복해도 이어지고, 모의 경기가 처음으로 돌아가거나 브라우저가 다시 연결되면 초기화된다.

명시적으로 데모를 열면 경기 상태는 모의 시계에 따라 바뀐다. **Pre-race**에서는 시작 타이어와 교체 1~3회를 편집하고, **Racing**에서는 다음 피트스톱을 조정한다. **DNF**에서는 전략 편집이 종료된다. Rust가 모든 선택 가능 랩의 복귀 순위와 앞뒤 차를 계산한다. 복귀 비교에서는 상대가 계속 주행한다고 가정한다. 기본 피트 손실은 데모 가정값 12.1초이며, 현재 랩에 SC/VSC가 발령되면 그 랩의 손실에 60%를 적용한다.

전략표의 Remaining time은 표시한 랩 시작부터 결승선까지의 주행·피트 시간이다. 같은 타이어 세트의 완료된 건조 정상 랩으로 페이스와 열화율을 추정하고, 표본이 없으면 데모 기준 페이스·컴파운드 계수를 쓴다. 비교 시 레이스 중에 확정한 후속 스톱도 포함한다. 약한 비가 처음 내릴 때는 두 랩 뒤 노면이 젖는다고 가정한다. 상대 피트 비율은 다섯 수명 시나리오 중 교체하는 비중이다. 실측 예측 정확도는 게임 로그로 검증해야 한다.

**My Race → Pit Strategy**에서 위아래로 A/B/C를 고르고 Confirm으로 적용한다. 주행 중 왼쪽은 피트 랩·타이어 편집, 오른쪽은 상대 분석이다. 추천은 재고·노면 제약을 확인한 뒤 동일한 다섯 시나리오에서 현재보다 앞서 완주하는 횟수, 평균·최악 순위, 타이어 수명 부족과 예상 시간을 차례로 비교한다. 화면의 횟수는 실제 승률 통계가 아니다.

실시간 레이스에서 확정하면 한국어 피트 설정 MFD의 다음 타이어를 선택하고 게임 화면을 다시 읽는다. F1 25를 전면에 둔다. 기본 F2와 MFD 아래·오른쪽 키를 사용한다. 게임에는 다음 정차용 컴파운드를 지정하며, 예정 랩은 대시보드에 저장한다. 피트 후 실제 장착이 일치하면 다음 정차용 타이어를 설정한다. 일시정지·녹화 재생에서는 게임 입력을 보내지 않는다. **Menu → Settings → Codex strategy**에서 계정에 표시되는 모델과 추론 강도를 설정한다. Request Codex plan은 같은 GP 스레드에 다음 정차 제안을 한 건 요청하고 Rust가 동일한 시나리오로 평가한다.

상단 **Session Analysis**에서 휠의 위아래로 항목을 이동하고 좌우로 Grand Prix와 Session을 고른다. **Lap comparison**에서는 Lap A·B, 채널, 거리를 바꾼다. **Session replay**에서는 스틴트를 고른 뒤 한 칸 내려 Confirm으로 재생·일시정지하고, 다음 Replay lap에서 좌우로 랩을 탐색한다. 키보드용 Search GP와 세션 JSON 내보내기도 지원한다. **Menu → Settings → Diagnostics**에서 라이브 수신 상태를 확인한다. 데모 주소에서는 모의 진단을 표시한다.

**Menu → Settings → Wheel Mapping**에서 **Previous screen**과 **Next screen**의 Bind를 눌러 각각 휠 버튼을 등록한다. Live Timing, My Race, Session Analysis 세 탭을 양방향으로 순환한다. 키보드는 `[`와 `]`로 이전·다음 탭, `1`과 `2`로 두 주행 화면을 바로 연다. 분석 화면에서는 위아래로 항목 이동, 좌우로 값 변경, Confirm으로 버튼 실행, Cancel로 직전 주행 화면 복귀가 가능하다.

검증은 `web`에서 `npm run lint`, `npm test`, `npm run build` 순으로 실행한다. 루트에서 웹 개발 의존성과 기존 Qt 데모 의존성을 설치한 Python 환경으로 `python -m pytest -q`를 실행한다. Windows에서 `python tests/my_race_smoke.py output/playwright`를 실행하면 임시 서버와 SDL 가상 휠을 사용해 Chrome A/B 캡처 4장을 생성한다. 기존 A탭 전체 회귀는 실행 중인 서버에 `python tests/web_smoke.py http://127.0.0.1:8765`로 검증한다.

## 이전 PySide6 시안

Start-PySide-Demo.cmd로 이전 A/B·휠 데모를 별도로 실행할 수 있다. 아래 조작 설명은 이 데모 기준이다.

- **A · 라이브 타이밍**: 전 차량의 GAP(선두 기준), INT(직전 순위 기준), 최근 랩·섹터·타이어, 스즈카 트랙맵과 이벤트.
- **B · 내 레이스**: 내 주변 순위, 추격·방어 페이스, 타이어, 피트 복귀 예상. 후보 선택 후 확정해야 앱의 계획이 바뀐다. 직접 설정에서는 값을 바꾼 뒤 마지막 ‘편집한 전략 적용’을 확정한다.
- **출발 전**: 상단 장면 선택 → 출발 전 → B탭에서 출발 타이어와 최대 세 번의 교체를 편집한다. 다른 장면을 선택하면 레이스가 진행된다.
- **데모 조작**: 18초에 한 랩씩 진행하고 마지막 장면 후 추격 장면으로 돌아간다. 상단에서 장면을 고르거나 일시정지할 수 있다. 경기 장면 변경 시 미확정 편집은 취소된다.

## 입력
1 / 2: A / B, ↑ ↓: 항목, ← →: 후보·값, Enter: 확정, Esc: 취소, Space: 재생 전환. 클릭은 후보 미리보기이며 아래의 확정·취소 버튼도 쓸 수 있다.

휠을 연결한 뒤 **휠 매핑 → 입력 등록**을 누르고 실제 입력을 한 번 준다. 다이얼은 기기 설정에서 앱솔루트 모드로 두고, 다른 위치에서 원하는 위치로 돌려 등록한다. 여러 위치를 같은 탭에 등록할 수 있다. 스틱의 방향 버튼 또는 POV 햇과 누름 버튼을 각각 등록한다. 매핑은 Windows 사용자별 앱 설정 폴더의 wheel.json에 저장한다.

## 개발
PySide6 UI / pygame SDL 조이스틱. race.py는 두 탭이 공유하는 샘플 상태와 분석 표시값을 제공한다. 앱에서 확정한 전략은 현재 실행의 앱 계획이다. 데모 차량의 실제 주행은 재현용 시나리오를 따른다. 게임 UDP, 전략 전송 및 AI 응답은 연결하지 않았다.

검증: 가상환경에서 `python -m unittest discover -s tests -v`.
